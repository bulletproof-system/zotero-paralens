# Zotero PDF 全文翻译与双语悬停对照实施规划

> **For Hermes：** 本文仅是实施计划；按阶段实现，每阶段先做失败测试，再做最小实现、运行验证并提交。尚未创建插件或翻译服务。

**目标：** 在 Zotero 中选择一篇可提取文本的 PDF，完成全文翻译，并在阅读时悬停原文或译文段落，双向高亮其对应段落；第二阶段扩展到句子级。

**架构：** Zotero 插件（TypeScript）负责附件、作业状态和阅读界面；**优先由插件直接启动本机 Python/BabelDOC 子进程，一次翻译对应一次后台作业，无须用户预先启动 HTTP 服务**。Python worker 调用 pdf2zh-next/BabelDOC 生成译文 PDF，并在翻译前后导出可定位的双语映射；插件依据映射命中段落并绘制临时高亮。原文附件不修改，译文另存为同一文献条目的子附件。先验证 Zotero 阅读器中悬停注入的可行性，不能安全实现时改用插件自建双栏 PDF 阅读视图。仅在子进程模式验证失败时考虑独立服务作为备选。Zotero 自身提供异步启动外部程序的接口，但仍需管理 Python 环境、作业生命周期与日志。[10]

**技术栈：** Zotero 7 稳定版及现用版本的兼容性验证、zotero-plugin-template、TypeScript、Python 3.12、pdf2zh-next/BabelDOC、PDF.js 或 Zotero 内置阅读器、pytest/Vitest。版本在技术预研通过后锁定，不盲目依赖私有 API。[1][5][8]

---

## 1. 已知事实、边界与待验证点

- BabelDOC 在中间表示（IL）中维护页面、段落、`box`、`debug_id`、`layout_id` 等字段；翻译跟踪文件在调试/保留工作目录时记录原文 `pdf_unicode`、实际输入 `input`、译文 `output`，但本身不是带原/译位置框的正式对齐 API。[2][4][9]
- 翻译后段落 `unicode` 会被译文覆盖，因此必须**在翻译前保存原文快照、排版后保存译文位置**，不能只拿最终 IL 或最终 PDF 反推。[1][2]
- LLM 路径可能批处理、合并跨页或跨栏段落；需要记录每个原始段落在批内的 ID/顺序及回填去向，而不是假设始终一段一请求。[3]
- Zotero Reader 有 `registerEventListener` 等界面扩展点，文档列出的主要是工具栏、选区弹窗、侧栏元素；**尚不能据此认定存在稳定的逐字悬停/覆盖层公开接口**。这决定技术预研必须先做，否则不要承诺原生 PDF 阅读器内直接悬停。[5]
- 已有 `zotero-pdf2zh` 实现 PDF 全文翻译与译文附件导入，可借鉴作业与附件流程，但本项目差异化目标是**双向、可定位的段落/句子悬停对齐**；先核验其协议和许可证，再决定独立开发还是复用。[6][7]
- MVP：英文→中文、数字原生 PDF、段落级、单本地服务、单附件手动启动；不承诺扫描 OCR、跨设备映射同步、完美段落识别、任意 Zotero 版本兼容。扫描件检测后说明不支持或要求用户先 OCR；不把“白底遮盖”误当完整 OCR。

## 2. 用户流程与产物

1. Zotero 选中 PDF 附件 → 菜单「全文翻译并建立对照」。首次配置语言、翻译服务和本地 Python 环境；密钥由插件经受控配置交给 worker，不写进命令行参数、映射文件或日志。
2. 插件以参数数组启动一次性本机 worker（不拼 shell 命令），传入经验证的附件路径与作业目录；通过受限配置文件/标准输入传密钥，监视作业目录的结构化进度、取消标记与退出状态。重试同一源文件时使用哈希判重，可明确选择覆盖或新版本。
3. 后台输出 `translated.pdf` 与 `mapping.v1.json`；插件先校验哈希、页数和映射版本，再将译文 PDF 作为同一文献的**新附件**导入，记录「原附件 key ↔ 译文附件 key ↔ 映射文件」。原附件不覆盖。[7]
4. 打开对照阅读：两份 PDF 并排，悬停任一侧段落时本侧和对侧暂时高亮；移出清除，点击固定/跳转（后续阶段）。没有可信映射时不猜测、不误高亮。

## 3. 映射数据契约（先写 Schema 与测试）

`mapping.v1.json` 使用**本次翻译内部稳定的段落 ID**，不要直接把 BabelDOC 的 `debug_id` 当跨版本永久 ID。持久绑定靠两个 PDF 的 SHA-256、附件 key、服务及数据格式版本；原/译页允许不同号，不以页号相同为前提。下面仅是拟定格式，并非 BabelDOC 现成输出：

```json
{
  "schemaVersion": 1,
  "source": {"sha256": "...", "attachmentKey": "...", "pageCount": 0},
  "target": {"sha256": "...", "attachmentKey": "...", "pageCount": 0},
  "segments": [
    {
      "id": "p-000001", "level": "paragraph", "status": "aligned", "confidence": 1.0,
      "source": [{"pageIndex": 0, "text": "...", "quads": [[0.1, 0.2, 0.4, 0.2, 0.4, 0.23, 0.1, 0.23]]}],
      "target": [{"pageIndex": 0, "text": "...", "quads": [[0.5, 0.3, 0.8, 0.3, 0.8, 0.33, 0.5, 0.33]]}]
    }
  ]
}
```

- `pageIndex` 从 0 开始；`quads` 坐标约定为**相对页面可见 CropBox 的归一化坐标、左上为原点**，且 4 个点顺序固定。保留源 IL/PDF 坐标到该约定的变换及旋转元数据，以应对旋转、裁切、缩放。一个段落可跨页、多行，每一行一个或多个四边形；不要用整块 bbox 遮住图表。
- 一个 segment 的 source/target 都是数组，支持跨页、跨栏、多对多；`status` 可为 `aligned`、`skipped`、`uncertain`、`failed`，仅 `aligned` 且坐标有效的记录参与悬停；保留原文、译文和质量/置信度信息以便人工纠错。
- 译文 PDF **和**映射文件须来自同一次任务。文件内容、页数或后端版本变化时使映射失效；重译后重新生成，不复用旧位置。

## 4. 实施任务（拟建项目路径）

以下文件路径均相对于将来建立的代码仓库根目录 `zotero-bilingual-align/`；**本次只创建本规划文件，不创建代码文件**。

### 阶段 A：可行性验证（必须先通过）

**任务 A1：** 建测试用数字 PDF：单栏、多栏、跨页段落、公式、图注、旋转/裁切页各一份。建立 `fixtures/` 和许可说明；记录 Zotero 版本、PDF 样本哈希、依赖版本。验证原始与译文 PDF 文本层是否可读。

**任务 A2：** 用锁定版 BabelDOC 翻译一份样本，在测试分支/受控适配器中观察 IL 在 `ParagraphFinder` 之后、翻译前、`Typesetting` 之后的字段和对象连续性；检查 `translate_tracking.json` 的 `page/cross_page/cross_column` 结构。产出 `docs/feasibility.md`：真实字段样例、生成位置、清理逻辑、拟插入的 hook、许可证核对。[1][2][3]

工作目录的保留与清理另按配置代码确认。[9]

**任务 A3：** 用模板造最小 XPI，在 Zotero Reader 注册工具栏按钮，验证能否在阅读 iframe 安全监听 pointer move、获得当前 page/viewport、增删临时 overlay，并在缩放、旋转、滚动、切换标签、卸载插件时清理。只在受支持入口能获取稳定页面生命周期时使用原生阅读器；若依赖内部 DOM/私有对象，记录版本耦合并转向**插件自建的双栏 PDF.js 阅读视图**（默认保底方案）。禁止将 hover 效果实现为 Zotero 永久注释。[5][8]

**阶段闸门：** 同一页测试段落可稳定双向高亮；缩放/旋转后位置仍正确；无法做到则先交付自建双栏阅读视图，不阻塞翻译后端。

### 阶段 B：后端与段落映射 MVP

**任务 B1：** 创建 `backend/worker.py`、`backend/models.py`、`backend/tests/test_jobs.py`：一次性本机 worker 接收作业配置文件路径与输入 PDF 路径、写出原子更新的 `status.json` 和 `result.json`；退出码反映成功/失败，作业目录保存供重启恢复，取消时释放翻译资源、清理未完成输出。插件创建作业目录并用参数数组启动，无 shell 拼接；密钥存于限定权限的临时配置并在完成后删除，禁止出现在进程参数、状态文件和日志。单测先用假翻译器，不消耗 API 费用；后续验证子进程结束后无孤儿进程。[10]

**任务 B2：** 创建 `backend/translator_adapter.py`、`backend/align_export.py`、`backend/tests/test_align_export.py`：在翻译前给 IL 段落分配本次内部 ID 并快照文本+字符/行几何；在译文排版后导出目标段落几何，按跟踪 ID 连接。处理跨页、跳过、公式占位、异常段落；不修改原始 PDF。优先通过明确的 BabelDOC 适配层/受控补丁实现，不把 debug JSON 当唯一数据源。先测失败→最小实现→测通过。

**任务 B3：** 创建 `backend/schema/mapping.v1.schema.json`、`backend/tests/test_mapping_geometry.py`：校验 ID 唯一、源/译附件哈希、页号范围、坐标范围、旋转/CropBox、跨页数组和跳过状态；模拟页面旋转、缩放、截断和译文扩行，逐四边形验证位置。不同 PDF 内容触发映射失效。

### 阶段 C：Zotero 插件及段落级双向悬停

**任务 C1：** 基于模板建立 `plugin/src/index.ts`、`plugin/src/modules/process.ts`、`plugin/src/modules/jobs.ts`、`plugin/src/modules/attachments.ts`、`plugin/tests/jobs.test.ts`：菜单/按钮启动任务；`process.ts` 探测隔离的 Python 环境与 BabelDOC 资源，调用 Zotero 的异步外部进程接口，追踪退出码、进度、日志、取消与 Zotero 重启后的残留作业；`attachments.ts` 导入译文附件。同文献重复运行不创建含糊的重复结果，失败不留下孤儿映射。核验普通条目、独立附件、只读/组库附件权限行为。[7][8][10]

**任务 C2：** 建立 `plugin/src/modules/mappingStore.ts`、`plugin/tests/mappingStore.test.ts`：映射存在插件可管理的数据目录，索引按库 ID + 原附件 key + 译附件 key；打开时检查 PDF 哈希、schema 和页数。MVP 为本机映射，**不同设备不会自动同步**；未来另设计导入/同步，不直接改 Zotero 数据库。

**任务 C3：** 建立 `plugin/src/reader/overlay.ts`、`plugin/src/reader/hitTest.ts`、`plugin/tests/hitTest.test.ts`：每个可见页建立四边形空间索引；将 pointer 坐标经 viewport 逆变换到归一化页面坐标，命中后查同一 segment 的另一侧 quads；在两侧绘制 `pointer-events: none` 的半透明 overlay，节流鼠标移动，移出、滚动、缩放、切标签时清除/重绘。原生 Reader 技术闸门不过时改用 `plugin/src/reader/dualView.ts` 的自建双栏视图，不靠文本字符串二次搜索来猜坐标。

**阶段 C 验收：** 打开 Zotero 中译文附件；段落悬停双向高亮、滚动缩放后不漂移、跨页可跳转；关闭/卸载后不留高亮或监听器。测试单份 PDF 从翻译到 Zotero 阅读完成真实端到端闭环。

### 阶段 D：句子级与产品化（后续，不阻塞 MVP）

**任务 D1：** 在 `backend/sentence_align.py`、`backend/tests/test_sentence_align.py` 对原/译段落分句，保留句子到字符/行四边形的偏移映射；先评估句界、缩写、引用、公式、跨行连字符及中英标点。不能用一句的外接矩形遮住相邻句。

**任务 D2：** 句子对齐优先用翻译阶段显式句 ID/结构化输出的试验路径；若影响译文质量或模型破坏 ID，再试多语句向量 + 单调动态规划；允许 1:N / N:1 和 `uncertain`，设置可配置阈值并提供人工修正。对低置信度句子退回段落高亮，绝不硬配。

**任务 D3：** 翻译服务设置、并发/费用控制、进度恢复、原/译同步滚动、点击锁定高亮、手工修正映射与导出语料；分别做兼容和性能回归。

## 5. 验证矩阵与验收标准

- **后端单测：** `pytest backend/tests -q`；包含段落 ID/跟踪回填、跨页跨栏、多行几何、旋转/CropBox、跳过/失败、取消与文件清理、无密钥泄露。
- **插件单测：** `npm test`（以实际模板脚本确认后固定）；包含命中测试、双向映射、失效哈希、页面变换、生命周期清理、重复任务处理。
- **端到端：** 用开发版 Zotero + 本地服务，对真实数字 PDF 运行一次完整翻译；检查 Zotero 原附件未改、译文可打开、双向悬停命中、滚动缩放后位置、重启后映射仍可用、替换 PDF 后自动失效。记录性能基线：长篇论文、快速滚动不明显卡顿；实际阈值由 A 阶段基准确定。
- **句子级上线门槛：** 建人工标注的多栏/公式/跨页样本集，量化 precision 与 coverage；未达标只开放段落级，句子级标记实验性。不要把未匹配句子伪装成准确对齐。

## 6. 风险与取舍

1. **Zotero 原生 Reader 悬停接口缺口：** 文档仅确认有限 UI 注入事件；自建双栏 PDF.js 是可控退路，但会少一些 Zotero 原生阅读体验。[5]
2. **BabelDOC 内部 API 变更：** IL/翻译器属于版本耦合代码，适配层锁定测试版本，升级时跑兼容测试；不要只依赖 `debug_id` 或调试文件。[1][4]
3. **两份 PDF 的句子不必严格一一对应：** 翻译有合并/拆分、段落有跨页；数据契约支持多对多与未匹配，产品显示真实置信度。[3]
4. **授权/部署与隐私：** 复用现有插件/翻译后端前核查许可证。插件可启动子进程，但机器仍需可执行 Python 和已安装的 BabelDOC/模型/字体资源；MVP 先提供可验证的环境路径及首次检查，后续再做自动安装，不把完整环境塞入 XPI。密钥不放命令行或日志，临时配置限制权限并按完成/取消清理；不允许未验证的任意文件路径进入 worker。[6][10][12]
5. **文件映射同步：** MVP 仅本机持久化；Zotero 同步译文附件并不等于自动同步对应关系，后续需要独立设计。
